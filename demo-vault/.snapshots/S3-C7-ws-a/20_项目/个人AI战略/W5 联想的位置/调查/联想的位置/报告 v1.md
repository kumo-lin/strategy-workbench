# 联想的位置 调查报告 v1

## Summary
- 要回答的问题：联想明年在商用 AI PC / 个人 AI 上该押哪一层、怎么拿到；凭什么是联想而不是微软；Qira 在企业买方这一侧有没有依据
- 一句话答案：明年应押机队整合与管理/服务层，不押端侧算力和 agent 本身；服务是增长与利润的加成，不是资产主体，而「自研整合层加微软生态合作」目前材料没有直接支持，只能作为待验证路径。依据是联想的机队整合广度[^1]、份额领先的装机基数[^2] 和 TruScale 同比增长 35%[^3]，需求侧换机由 Windows 10 终止支援推动[^4][^5]，AI PC 采纳放缓、PC 单季出货同比衰退 20.1%[^6][^7]；但待验证：服务业务整体规模不大、只是利润率最高[^8]，微软已覆盖已纳管 Windows 设备的集中配置、身份与隔离[^9][^10][^11]，Qira 企业侧官方可管能力与采购案例仍缺、第三方企业版报道只到 C 级[^12][^13][^14]，所以三条原判断都需要修正，不能写成已成立。

## 逐个假设
### H1 联想的资产集中在机队整合和服务这一层，明年应该押管理 / 服务层，用自研整合层加微软生态合作的方式拿到，而不是押端侧算力或 agent 本身。  [[W5-H1 联想的资产在机队与服务层]]
- 提议的判断：需要修正（AI 提议，等人拍板后才生效）
- 修正后的假设：联想的可押资产在机队整合这一层：它能通过统一的软件和服务层整合并管理更多设备类别，并且有份额领先的PC装机基数；服务侧在增长、利润率最高，但规模仍不大，因此不能说联想的资产集中在服务层。明年押管理/服务层，定位应是守住机队入口和随设备交付的服务，而不是把可管理性当作溢价来源；换机预算吃紧时，买方先看的是换机节奏和运行成本，AI能力不是首要考量，所以端侧算力或agent本身不宜当作主押方向。至于用自研整合层加微软生态合作拿到，材料只支持一点：整合层必须开放、能并入买方现有的终端管理与日志体系；这条路径目前只有买方侧的要求作为线索，还没有直接证据。

### H3 Qira 现在偏个人体验，企业买方一侧还没有采购需求和预算依据；它要先成为 IT 可管的 agent 才进得了企业评审，和押管理栈是先后关系，不是互斥。  [[W5-H3 Qira要先成为IT可管的agent]]
- 提议的判断：需要修正（AI 提议，等人拍板后才生效）
- 修正后的假设：Qira 眼下对外可见的仍是个人版定价和个人设备覆盖，官方材料里看不到成形的企业信息技术管理能力，也找不到企业规模采购的案例；受监管行业对员工端智能体的功能边界、数据权限和审计追溯有原文明确的硬性要求，而联想承诺的安全合规认证目前尚未拿齐。所以在有统一机队管理的企业里，Qira 得先补齐信息技术可管能力才进得了评审，与押注管理栈是先后关系而非互斥；但在业务线自带预算、绕过信息技术部门的场景里，这条先后关系不成立。
- 修正后的论断，逐条过证据门槛（至少 2 个独立来源、其中至少 1 个 A/B 级）：
  - H3-A1（已验证：2 个独立来源，最高 A 级）：受监管行业要求员工端人工智能划定功能边界、限定系统和数据权限、明确岗位责任并可追溯，日志留存不得低于业务存续期[^26][^21][^22][^58]

## 对 workplan 的影响
- 需要修正「联想资产集中在服务层」这一假设：改为「资产在机队整合层，服务是增长与利润的加成」，并把「自研整合层加微软生态合作」标为待验证路径，不作为已证实方案。
- 需要修正「微软之外联想只剩机队硬件与服务」这一假设：不能把「硬件层固件与带外控制」写成联想独有差异；待验证：联想在厂商管理门户入口上不占优，需补证或改写对外口径。
- 需要修正「Qira 企业买方一侧没有依据」这一表述：官方侧仍缺 IT 可管能力文档和采购案例，第三方企业版报道只到 C 级，应写成待验证而不是否定。
- 追加调查：以及惠普、戴尔、英特尔设备管理层位次。
- 追加调查：核实「换机由 Windows 10 终止支援推动、AI 能力不是首要考量」的买方调研原文，以及服务收入增长是否主要来自管理服务。
- 和 W6–W7 比较选项负责人对齐：把「押哪一层」的备选收敛为机队整合与管理/服务层、端侧算力、agent 本身三类，并把「怎么拿到」拆成自研、合作、收购分别需要补的证据。
- 和高层周会口径对齐：把「IT 能不能管」落成可验收条件，包括集中部署配置、数据权限边界、审计追责和日志可导出。
- 要问专家：跨设备类别的统一管理层是必选项还是可选项；开放日志并入 Intune、SCCM 和 SIEM 后是否愿意为随设备交付的管理服务单独付订阅费、走哪个预算科目。
