# 专家访谈（模拟）：大型制造企业 IT 基础设施负责人

> **模拟的访谈记录**（simulated: true），演示用。受访者是虚构的，**不是事实证据**，不能在报告里当作 A/B/C 级信源引用来支持结论；它的作用是演示"专家输入怎么沉淀、怎么引用"，以及资料里的缺口怎么变成要问专家的问题。真实专家访谈由人去做，AI 不能模拟专家回答。

访谈者：Junior A　受访者：某大型制造企业 IT 基础设施负责人（虚构，管理数万台终端）

**Junior A**：先从现状问起。你们现在怎么管员工用 AI 工具？有没有白名单？

**受访者**：有，但不是那种一刀切的白名单。我们分三层：第一层是完全禁止的，把内部代码、工艺参数、客户名单贴到公网的消费级工具里，这个碰红线；第二层是受限使用的，允许用，但必须走企业版、走 SSO，日志要能落到我们这边；第三层是开放的，一般文案、翻译、会议纪要这类，员工用什么我们基本不管。数据分级是跟着走的，公开数据、内部数据、机密数据三档，机密数据原则上不出内网，能不能进 AI 工具要单独过一遍评审。老实讲，规则写得挺清楚，落地是另一回事，很多员工根本不知道该把手上这份文件归到哪一档，这个我们还在补培训。 ^e1

**Junior A**：如果厂商把个人 agent 直接预装在 PC 上，出厂就在那儿，你们第一批问题会是什么？

**受访者**：第一句一定问数据去哪、存哪儿、留存多久、会不会回流到厂商的模型训练里。第二句是有没有企业级的开关，能不能由我们统一下发策略，甚至在 BIOS 或者设备管理那一层就关掉，不是靠员工自己点同意。第三句是日志，能不能导出、能不能进我们的 SIEM，出了事我要查得到是谁、什么时间、把什么内容交给了 agent。第四句是它跟现有工具怎么配合，我们这边 Intune、SCCM 那一套都在跑，如果这个 agent 是个黑盒，自己一套更新、自己一套凭据，那就很麻烦。还有一点容易被忽略，它的权限边界在哪，能不能读本地文件、能不能调浏览器，这决定了它到底是个工具还是一个风险面。 ^e2

**Junior A**：听起来可管理性是硬门槛。那在采购的时候，它是不是加分项？

**受访者**：是门槛，不是加分项。这句话我想说清楚。我们评估的顺序是先过合规和技术评审，过不了就直接出局，但过了之后，几个候选放在一起比，可管理性其实拉不开差距，因为大家都说自己可管。最后拍板的往往是价格、换机周期怎么衔接、和现有合同的打包方式。你多给我一套管理能力，我不会因此多付很多钱，因为我的运维人力是固定的，多一套控制台反而多一份活。 ^e3

**Junior A**：那预算呢？这笔钱从哪出？

**受访者**：看形态。如果它是跟着 PC 来的，那就是硬件预算的一部分，摊在设备成本里，这种情况下我对单价很敏感，因为量大。如果是单独订阅，那就走软件预算，但它得跟现有的安全软件、协同工具去抢同一个池子，我会问它替代了什么。现在也开始出现一种独立的 AI 预算，但盘子很小，通常是创新基金或者某个业务部门自己出的钱，可持续性差，今年有明年不一定有。至于为"可管的个人 AI"多付钱，我的态度是愿意小幅溢价，前提是它真的减少了我的管理成本或者降低了事件处置时间，而不是把责任推给我、再多给我一个控制台。 ^e4

**Junior A**：你刚才说可管理性是门槛，我能不能理解成，只要合规过了，你们其实不太在意它是不是"个人 AI"？

**受访者**：对，甚至我要说一句反面的。管得太死，员工会绕过去。我们之前推过一轮很严的终端管控，结果呢，员工拿自己的手机拍屏幕、用个人账号在浏览器里开外网工具，我们一样看不见，风险反而更大，因为你连日志都没有。所以我不认为"管住"本身就是价值，把员工逼到影子 IT 里去，是最坏的结果。还有一层，采购到最后还是看价格和换机周期，管理能力只是门槛，不是加分项。厂商如果拿"可管理"当卖点来溢价，我这边很难过。我更希望看到的是它在放开使用的同时，让我看得见、追得到，而不是简单地把功能锁掉。 ^e5

**Junior A**：这个角度挺关键的。你觉得目前的资料里，哪一块是看不到、还需要继续找专家问的？

**受访者**：有一个缺口我一直没找到答案：当 agent 真的替员工做了动作，比如自动填了一个表单、发了一封邮件、改了一份文档，责任怎么算，审计上怎么界定"这是人批准的"还是"这是 agent 自己做的"。现在的材料基本都在讲能力、讲体验、讲怎么管，很少讲清楚出问题之后的追溯链条，以及企业内控和审计部门能不能接受。这个问题不同行业答案可能完全不一样，制造业、金融、医疗差别很大，我建议你们去找几个受监管行业的 IT 负责人再问一轮，别只问我们这种。 ^e6
