# so what 提炼

> 用途：调查结果出来以后，把"查到了什么"变成"这对要做的决策意味着什么"。写报告的 Summary、准备结论审批、搭 storyline 之前都要做。
> 一条 so what = **一个判断 + 它依赖的证据 + 它对决策的含义**。缺了任何一样，都只是一条 fact。
> **AI 和人的分工**：AI 帮团队把思考做快、把脏活做掉、把工作的 context 沉淀下来；它可以按团队认可过的方法给出结论、证据和推荐判断，但**最后做判断的是人**。所以本篇里 AI 写出的每个判断和推荐都标"提议"，状态（提议 → 已确认 / 已否决）只能由人来改。

## 什么时候用

- 一次调查的报告要写 Summary。
- 准备结论审批（Senior 会问"所以呢"）。
- 几个 Workspace 的结论要汇总成项目层的判断。

## 三级梯子

> 本节的例子只演示写法。例子里的事实没有经过资料验证，不能当证据引用，以资料库为准。

| 级 | 回答什么 | 在报告里写在哪 | 例 |
|---|---|---|---|
| What | 事实是什么 | 每个假设下的证据 | 某份 CIO 调研里，安全和数据管控是部署员工 AI 的头号顾虑 |
| So what | 这对我们的问题意味着什么 | 每个假设的 So What，再合成子问题的回答和核心问题的回答 | 企业买员工端侧 AI 的门槛不在算力，在"IT 管不管得住" |
| Now what | 对联想的决策意味着什么：做什么、量级多大、看什么指标 | Summary 里的"AI 的推荐判断" | （提议）商用 AI PC 的差异化押在管理和安全栈上，不再堆 NPU 算力；先在少数几家大客户试点，看它们的 IT 会不会把这一项写进采购资格条款 |

只到 What 的是资料摘要；到 So what 是分析；到 Now what 才是战略部要交的东西。Now what 要写到能执行、能拍板：做什么、量级多大、看什么指标，并标"提议"，由人拍板。

## 步骤

1. **先列判断**：每个假设的提议判断（成立 / 需要修改（改成……）/ 不成立 / 证据不足）。so what 只能从判断出发，不能从单条资料出发。判断还没被人拍板，由它推出的 so what 也只是提议。
2. **每个假设写一条 So What**：这个判断对它回答的子问题意味着什么。一条就够，写不出一条，说明判断本身还不清楚。
3. **逐级往上组装**：
   - 用假设的判断和 So What，写出每个子问题的回答；
   - 再用各个子问题的回答，组装出核心问题的回答；
   - 写一句"为什么这几个回答足以回答核心问题，少了哪一个就答不了"。
   核心问题的回答里，不能出现子问题回答之外的新理由。
4. **找意外**：和大家原来以为的不一样的地方，往往是最有价值的 so what。问："读者看完会不会说'我早知道了'？"会，就再往下挖一层。
5. **连到决策**：对核心问题的回答问"所以呢"，一直问到它碰到 workplan 里写的那个决策为止。通常要问 2–3 次。
6. **推到 Now what，写成"AI 的推荐判断（提议，待你拍板）"**。写清楚：
   - **做什么**：一个具体动作，谁来做。
   - **量级多大**：投入、规模或时间的大概范围。有证据就挂证据；没有就写清楚是怎么估的，并标"推断"。宁可给一个区间，也不要编一个精确的数。
   - **看什么指标**：做对了会看到什么、做错了会看到什么、什么时候看。
   - **其他选项和不选的理由**：把决策的其他选项都列出来（包括自研 / 合作 / 收购这一维），每个用一句话说为什么不选。理由要是证据或判断，不能是"它只能当补充"这种用结论解释结论的话。
   - **什么情况下要改**：出现哪条证据、哪个指标到了哪里，这个推荐就要改。
7. **排序**：按对决策的影响大小排，不按调查的顺序排。最多 3 条。
8. **标出依赖**：每条推荐写清楚靠的是哪几个子问题的回答。依赖"证据不足"的子问题，要明说这条推荐有条件。
9. **标出边界**：在什么条件下成立；反证说明了什么风险。

## 怎么检验一条 so what

- **"那又怎样"测试**：再问一次"那又怎样"，如果还有更深一层没说，就还没到底。
- **换名字测试**：把"联想"换成"戴尔"或"惠普"，这句话还完全成立吗？完全成立，说明还没有落到联想的位置上（份额、渠道、产品线、客户结构）。
- **组装测试**：核心问题的回答里，拿掉任何一个子问题的回答，还成立吗？还成立，说明那个子问题不必要。把所有子问题的回答放在一起，能直接推出核心问题的回答吗？推不出，说明拆得不充分，或者回答里多了没有出处的东西。
- **可追溯**：每个词都能追到证据或者判断。追不到的，要么删，要么标"推断"。
- **可行动**：读完知道该多做什么、少做什么、先做什么。
- **对手测试**：拿这一层最强的对手来比（例：管理 / 安全栈这一层是微软的 Intune 和 Agent 365）。对手已经做了，这条 Now what 还成立吗？
- **可拍板**：读的人能直接回"同意 / 不同意 / 改成 X"吗？推荐、其他选项、改的条件都写了，才算可拍板。
- **不过度**：没有说得比证据更满。"证明了"和"说明了一个迹象"不是一回事。

## 好的 so what 和差的 so what

> 本节的例子只演示写法。例子里的事实没有经过资料验证，不能当证据引用，以资料库为准。

| 差的 | 问题在哪 | 好的 |
|---|---|---|
| "AI PC 市场快速增长，前景广阔。" | 只是 What，而且没有出处 | "AI PC 出货在涨，但主要是 Windows 10 停服带来的换机，企业为 AI 本身付溢价的证据很弱 → 明年不能把'AI'当成商用换机的主卖点。" |
| "企业很重视安全。" | 太泛，换谁都成立 | "CIO 不部署员工 AI 的头号原因是数据管控 → 谁能把端侧 AI 做成 IT 可管的，谁就拿到企业预算；这和联想现有的商用管理服务是同一个入口。" |
| "建议持续关注 agent 发展。" | 没有判断，也没有行动 | "员工 agent 的入口在操作系统和办公套件手里 → 联想单做 agent 赢不了，应该押在'让企业 IT 管得住别人的 agent'。" |
| "建议联想加强管理和安全能力。" | 有方向，但没有量级和指标，没列其他选项，也没标提议 | "（提议，待你拍板）把管理 / 安全栈做成能写进采购资格条款的证明物，先在少数几家大客户试点，看这些客户的 IT 会不会把它写进招标要求。不选'自研一整套管理平台'：最强的对手已经有了；不选'继续堆算力'：买方不为 AI 本身多付钱。如果试点客户的 IT 还是只看价格和换机周期，这个推荐要改。" |
| Summary 逐个假设列判断："H1 需要修正……H2 需要修正……H3 需要修正……" | 没有回答核心问题，读的人要自己拼 | 先一句核心问题的回答，注明由哪几个子问题的回答组装而成；再列各子问题的回答，写为什么这几个就够了 |

## 常见错误

- **把 Summary 写成目录**："本报告分析了 A、B、C。"
- **只列判断，不组装。** 每个假设都判了，核心问题却没有回答。
- **so what 太多。** 十条 so what 等于没有 so what。每个假设一条，推荐最多 3 条。
- **只说好消息。** 反证和"证据不足"也会产生 so what（例："这件事我们还不知道，而它决定了 X，所以下一步先问专家 Y"）。
- **跳过 So what 直接给 Now what**：建议没有判断支撑，Senior 一问就倒。
- **把推荐写成定论。** "联想应该……"没标提议、没列其他选项，读的人只能整句接受或整句推翻。
- **AI 改了状态。** 提议 → 已确认 / 已否决只能由人来改；AI 只能在文字里写"建议改成……"。
- **用形容词代替判断**："显著""巨大""关键"。
- **用模板词代替判断**："收窄""落点""层面"。写清楚只在什么条件下成立、改成了什么。
