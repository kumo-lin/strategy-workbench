# 联想的位置 调查报告 v2

## Summary
- 核心问题：联想明年在商用 AI PC / 个人 AI 上该押哪一层、怎么拿到；凭什么是联想而不是微软；Qira 在企业买方这一侧有没有依据
- 回答（一句话）：联想明年能押的是机队整合与随设备交付的服务，管理能力按准入要求做、并进客户已有的管理工具，不当溢价卖点；这一层里跨设备机队和硬件层控制不是联想独占，能说的是随设备交付的服务加补位；Qira 在企业买方一侧的依据只有单一媒体来源、合规认证还在规划中，明年的差异化不能建在「Qira 已有企业采购依据」上。（由 Q1、Q2、Q3 的回答组装而成）
- 问题树：核心问题 → Q1 联想该押哪一层，怎么拿到？／Q2 凭什么是联想，而不是微软？／Q3 Qira 在企业买方这一侧有没有依据？
- 各子问题的回答：
  - Q1 → 已验证的是：换机预算吃紧时买方看价格与换机周期，2025 年企业换机的推力是 Windows 10 终止支援、不代表企业为 AI 功能采购[^1]，AI PC 涨价把 50% 渗透推迟到 2028 年[^2]；联想已经能提供随设备交付的服务，TruScale DaaS 覆盖设备生命周期，产品组合把服务、TruScale DaaS 与端到端方案打包[^3][^4]。还没证实的是：联想的资产主体是硬件与商用渠道，PC 全球份额 24.2%、领先地位进一步加强[^5]，服务是增长引擎但收入占比仍小，TruScale 同比增 35%[^6]。所以明年该押的是机队整合与随设备交付的服务，管理能力按准入要求做、并进客户已有的管理工具，不当溢价卖点。
  - Q2 → 已验证的是：微软在 agent 的集中配置和身份上已有可用管控，Intune 与 Agent 365 能设策略、监控风险并治理 agent[^7]，Intune 与 Entra ID 能用于设备带内管理[^8]。还没证实的是：跨设备类别和硬件层带外不是联想独有——Intune 已支持 Windows、Android、iOS/iPadOS、macOS[^9]，Intel vPro 可在芯片层远程管理机队并恢复故障[^10]，惠普已有完整带外管理[^11]，戴尔用 AMD 管理控制台做带外[^12]，测试时联想还没有合作门户、BIOS 策略要手工发布[^13][^14]。所以跨设备机队和硬件层不能当成联想独占的差异化，说法要改成随设备交付的服务，以及在微软管控缺口处补位。
  - Q3 → 受监管行业的要求是明确的：科学设定人工智能的功能边界、系统和数据权限、做到可落实可追溯[^15]，具备日志审计能力、日志保存期限不低于业务存续期[^16]，谁使用谁负责、明确各方分工和权责[^17]。还没证实的是：Qira 的合规认证还在规划中，SOC 2 Type II 安排在 2026 年第四季度、ISO 27001 在 2027 年第一季度、FedRAMP Moderate 在 2027 年第二季度[^18]，企业侧管理能力只有单一媒体来源称已经具备[^19][^20]，没有企业规模部署或采购 Qira 的案例，只有每设备每月 8 美元起的定价[^21]，对外售卖形态仍是个人版按用户月费[^22] 和高端设备增值服务[^23]。所以企业买方这一侧的依据只有单一媒体来源、合规能力还在规划中，Qira 要先成为 IT 可管的 agent 才进得了企业评审，和押管理栈是先后关系，不是互斥。
- 为什么这几个回答足以回答核心问题：三问都答了：Q1 说清联想的资产落在机队与服务这一层、该押随设备交付的服务；Q2 说清这一层里微软已经管住 agent 的配置和身份、跨设备与硬件层也不是联想独占，所以要不要由联想来做要靠服务补位来答；Q3 说清 Qira 放在什么位置——先补齐 IT 可管能力，和押管理栈是先后关系。少了 Q1 不知道该押哪一层，少了 Q2 只知道这一层值得做、不知道该不该由联想来做，少了 Q3 说不清押管理栈和已经发布的 Qira 是互补还是冲突。这次没查的子问题没有，端侧算力和 agent 本身作为「不押」的选项在 H1 的假设和反证里看过，员工侧和买方采购逻辑不在本次范围。

## Q1 联想该押哪一层，怎么拿到？

### 假设 H1：联想的资产集中在机队整合和服务这一层，明年应该押管理 / 服务层，用自研整合层加微软生态合作的方式拿到，而不是押端侧算力或 agent 本身。  [[W5-H1 联想的资产在机队与服务层]]
- 提议的判断：需要修改（改成：联想的资产集中在机队规模、商用渠道和随设备交付的服务上：PC 份额领先、TruScale 增长快，但服务收入占比仍小、硬件仍是营收主体；换机预算吃紧时，买方看的是价格和换机周期，而不是 AI 硬件能力。因此，明年该押的是机队整合与随设备交付的服务（TruScale DaaS）；管理能力要作为进入企业评审的准入要求，并入客户已有的管理工具，不拿它当可以溢价的卖点）
- 理由：必须成立的条件(1)只成立一半：PC 全球份额 24.2%[^5]，商用渠道与机队基础大；但智能设备业务收入 171 亿美元、同比增长 27%[^25]，服务业务规模不大[^26]，PC 仍是最大基本盘[^27]，「服务收入占比高」这一半不成立。条件(2)成立：2025 年企业换机推力是 Windows 10 终止支援、不代表为 AI 功能采购[^1]，AI PC 涨价把 50% 渗透推迟到 2028 年[^2]，AI PC 采用因关税与采购暂停而放缓[^28]。条件(3)满足：支持证据来自联想、數位時代、Gartner、钛媒体等不同发布方，含 A、B 级。假设里「押管理 / 服务层」可以当差异化、以及「自研整合层」这两半，只有模拟专家访谈提出不同意见[^29][^30][^31]，不计入 A/B 级，不足以推翻，但足以要求改假设。
- So What：联想明年该押的是机队整合与随设备交付的服务，管理能力按准入要求做、并进客户已有的管理工具，不当溢价卖点；服务收入占比仍小，说明这条线要靠随设备捆绑做出规模，而不是靠单独订阅。
- 修改后的假设拆成几条，逐条对照判断标准（至少 2 个独立来源、其中至少 1 个 A/B 级）：

  - H1-A3（已验证：2 个独立来源，最高 B 级）：换机预算吃紧时，买方看价格与换机周期，不是 AI 硬件能力：2025 年企业换机的推力是 Windows 10 终止支援、不代表企业为 AI 功能采购，AI PC 涨价把 50% 渗透推迟到 2028 年。[^1][^2][^28]

### Q1 的回答

已验证的是：换机预算吃紧时买方看价格与换机周期，2025 年企业换机的推力是 Windows 10 终止支援、不代表企业为 AI 功能采购[^1]，AI PC 涨价把 50% 渗透推迟到 2028 年[^2]；联想已经能提供随设备交付的服务，TruScale DaaS 覆盖设备生命周期，产品组合把服务、TruScale DaaS 与端到端方案打包[^3][^4]。还没证实的是：联想的资产主体是硬件与商用渠道，PC 全球份额 24.2%、领先地位进一步加强[^5]，服务是增长引擎但收入占比仍小，TruScale 同比增 35%[^6]。所以明年该押的是机队整合与随设备交付的服务，管理能力按准入要求做、并进客户已有的管理工具，不当溢价卖点。

## Q2 凭什么是联想，而不是微软？

### 假设 H2：微软（Windows、Intune、Agent 365、执行隔离）已经覆盖 agent 的集中配置和身份、数据边界；联想剩下的差异化只有跨设备类别的机队整合、硬件层（固件和带外）控制和随设备交付的服务。  [[W5-H2 微软之外联想还剩机队硬件与服务]]
- 提议的判断：需要修改（改成：需要缩小为：微软在集中配置和身份上已有可用管控；跨设备机队和硬件层不是联想独有，联想相对能主张的差异化要落到随设备交付的服务，以及在微软管不到或管不好的地方补位）
- 理由：条件(1)成立：微软官方称 Intune 与 Agent 365 可设策略、监控风险并治理 agent[^7]，独立评测也用 Intune 加 Entra ID 做带内管理[^8]。条件(2)不成立：Intune 已支持 Windows、Android、iOS/iPadOS、macOS[^9]，Intel vPro 可在芯片层远程管理机队并恢复故障[^10]，硬件层不是微软管不到、更不是联想独占。条件(3)也不成立：惠普已有完整带外管理[^11]，戴尔用 AMD 管理控制台做带外[^12]，测试时联想还没有合作门户、BIOS 策略要手工发布[^13][^14]。所以原假设中「联想剩下的差异化只有跨设备机队和硬件层控制」这一半被 A 级反证推翻，只能改成随设备交付的服务加补位，不能把跨设备或硬件层当独占差异化。
- So What：不能把跨设备机队或硬件层当成联想独占的差异化；如果还要押管理/服务层，说法要改成随设备交付的服务和在微软管控缺口处补位，并先验证买方是否为此付费。

## Q3 Qira 在企业买方这一侧有没有依据？

### 假设 H3：Qira 现在偏个人体验，企业买方一侧还没有采购需求和预算依据；它要先成为 IT 可管的 agent 才进得了企业评审，和押管理栈是先后关系，不是互斥。  [[W5-H3 Qira要先成为IT可管的agent]]
- 提议的判断：需要修改（改成：Qira 在企业买方一侧的依据目前只来自单一媒体来源（企业版按设备每月 8 美元起、经 Lenovo Device Intelligence 做策略执行并留审计日志[^21][^19]），联想的 SOC 2 Type II、ISO 27001、FedRAMP Moderate 认证分别安排在 2026 年第四季度、2027 年第一季度、2027 年第二季度[^18]；受监管行业对功能边界、系统和数据权限、责任可追溯和日志审计的要求已经明确[^15][^16][^17]，Qira 要进企业评审仍须先补齐这些 IT 可管能力，和押管理栈是先后关系）
- 理由：条件(3)有 A 级证据支撑：受监管行业要求设定功能边界、系统和数据权限并做到可追溯[^15]，要求数据安全基础设施支持身份管理、行为监测和日志审计[^16]，坚持谁使用谁负责、明确各方分工和权责[^17]。条件(1)只支持一半：联想承诺的 SOC 2 Type II、ISO 27001、FedRAMP Moderate 认证分别安排在 2026 年第四季度、2027 年第一季度、2027 年第二季度[^18]，企业侧管理能力只有单一媒体来源称已经具备[^19][^20]，没有联想官方文档印证。条件(2)没有证据：只有每设备每月 8 美元起的定价说法[^21]。Qira 对外可见的售卖形态仍是个人版按用户月费[^22] 和高端设备增值服务[^23]，所以原假设「企业买方一侧还没有依据」要改成「依据只有单一媒体来源、合规能力还在规划中」。
- So What：明年商用 AI PC 的差异化不能建立在「Qira 已有企业采购依据」上；押管理栈要先把 IT 可管能力补齐、拿到联想官方文档和合规认证，Qira 的企业侧依据目前只有单一媒体来源。
- 修改后的假设拆成几条，逐条对照判断标准（至少 2 个独立来源、其中至少 1 个 A/B 级）：

### Q3 的回答

受监管行业的要求是明确的：科学设定人工智能的功能边界、系统和数据权限、做到可落实可追溯[^15]，具备日志审计能力、日志保存期限不低于业务存续期[^16]，谁使用谁负责、明确各方分工和权责[^17]。还没证实的是：Qira 的合规认证还在规划中，SOC 2 Type II 安排在 2026 年第四季度、ISO 27001 在 2027 年第一季度、FedRAMP Moderate 在 2027 年第二季度[^18]，企业侧管理能力只有单一媒体来源称已经具备[^19][^20]，没有企业规模部署或采购 Qira 的案例，只有每设备每月 8 美元起的定价[^21]，对外售卖形态仍是个人版按用户月费[^22] 和高端设备增值服务[^23]。所以企业买方这一侧的依据只有单一媒体来源、合规能力还在规划中，Qira 要先成为 IT 可管的 agent 才进得了企业评审，和押管理栈是先后关系，不是互斥。

## 对 workplan 的影响
- H1 要改：把「服务收入占比高」从必须成立的条件里去掉，改成这条线要靠随设备捆绑做出规模，管理能力按准入要求处理、并进客户已有的管理工具。
- H2 要改：删掉「跨设备机队和硬件层控制是联想独占的差异化」这一半，说法改成随设备交付的服务加补位；同时把 H2-A2、H2-A3 标为待验证，不能当结论用。
- H3 要改：把「企业买方一侧还没有依据」改成「依据只有单一媒体来源、合规能力还在规划中」，并写明 Qira 与押管理栈是先后关系。
- 追加调查：Intune、Agent 365 和 Windows 执行隔离覆盖可管理性三层中的哪几层、哪些设备和 agent 管不到；联想随设备交付服务的具体内容和买方付费证据；惠普、戴尔、联想在服务层的直接对比；agent 自主执行动作后的审计与责任追溯在企业内控里怎么处理。
- 要和 W6–W7 的比较对齐：候选选项里把管理能力从差异化项挪到准入要求，比较表按这个改，并把端侧算力、agent 本身作为「不押」的对照项保留。
- 要问专家：最近一次 PC 换机或设备即服务采购里，服务是随设备打包进硬件预算还是单独订阅走软件预算、各占多大；机队管理在评标里是准入要求还是评分项；把机队管理做进现有 Intune、SCCM 而不另给一套控制台，采购意愿有什么不同；愿意为随设备交付的服务多付多少。
- 要问专家：Qira 企业版的策略下发、按员工或部门开关、日志导出各自交付到什么程度、由哪个控制台管；SOC 2 Type II、ISO 27001、FedRAMP Moderate 的认证进度会不会影响受监管行业客户的评审时间表。
