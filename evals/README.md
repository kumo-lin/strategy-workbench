# Evals（D-15）

```bash
pnpm eval                      # 5 条用例，每条 3 次，真实模型
pnpm eval --cases 1,4 --runs 1 # 只跑一部分
```

- 模型：快照里的 `90_配置/模型.md`（`active: deepseek` → deepseek-flash）。key 从 `.env.local` 读，不会打印。
- 数据：`demo-vault/.snapshots/S3-C7-ws-a`（C7 跑完以后的 WS-A）。**每次运行复制一份**到 `.scratch/evals/<时间>/`，只写副本，demo-vault 只读。万一有代码退回去用全局 vault，`VAULT_DIR` 也指向 scratch 里的一份副本。
- 结果：`evals/results/<日期>.md`。同一天多跑几轮就追加在后面。没通过的那次，结果里附原文摘录。
- 判定：能用规则判的都用规则判（`evals/judges.ts`，有单元测试 `tests/evals/judges.test.ts`）。只有 ① 在规则没过时交给 LLM 判，结果里标“LLM 判定”，判定标准原文也写在结果文件末尾。

| 用例 | 怎么跑 | 怎么判 |
|---|---|---|
| ① G1 comment「我没看懂，所以这个调查结果的SoWhat是什么」 | 把快照退回到“G1 通过、m1 还没处理”（删掉 workplan v2），以 Junior A 的身份发出“和 AI 一起解读”按钮的那句话，取 AI 第一次 `ask_user` 给出的选项 | **规则**：有一个选项写了 “now what”。规则没过时再交给 **LLM 判定**：有一条理解的意思是“结论没有落到对联想战略 / 下一步行动的含义”（标准见 `NOW_WHAT_LLM_CRITERION`） |
| ② 反证或“证据不足” | 小调查，计划 v1 只跑论点 C2（可管理性三层是采购必要条件） | **规则**：论点下面至少有一条带资料引用的反证，或者写了“证据不足” |
| ③ 引用和数字 | 同 ② 的那次运行 | **规则**：每条 `[[资料#^cN]]` 都能在资料里找到那一块，并逐字对上前面的引文；正文里的统计数字（百分比、小数、带单位的数）都能在报告引用过的资料块里找到。“怎么查的”、标题、模型知识行不算；年份、个位数的结构计数（2 家、3 层）不算 |
| ④ 知识库用到了哪些笔记 | 同 ② 的那次运行 | **只记录，不判通过**（D-17）：报告里链接到的会议、决定、专家输入、高层逻辑、方法库、预置资料，分“出发点”和“正文”列出来，留给打分用 |
| ④′ 出发点引用了高层指示 | 同 ② 的那次运行 | **规则，三项都要过**（D-17，PRD v0.7 §11.1）：(a) 报告里有系统写的“这次调查的出发点”；(b) 它引用了高层周会 ^m1，引文里有「重点看 IT 能不能管」；(c) 这条引用过 check_citations（块存在，引文和原文逐字对上） |
| ⑤ S1 | 桩 | S1 做不做还没定 |

②③④④′ 共用同 3 次小调查，所以“每条 3 次”是同 3 次运行的几种判定。D-17 以后不再和普通模式比结论，eval 里也就不再跑普通模式。

## 工作计划对话评测（D-56）

pnpm eval:workplan                       # 5 题 × 3 次，真实模型，约 10 分钟
pnpm eval:workplan --questions 2,4 --runs 1
pnpm eval:workplan --dry                 # 用脚本化的假模型，只验证流程

结果追加在 evals/results/workplan-<日期>.md：每次运行的对话、规则检查（没有文件名 / 没有 markdown / ≤ 80 字 / ≤ 1 个问句 / 不夸奖 / 不列能力清单 / 不替人宣布提交）和模型打的语气分（只记录，不判通过）；每次末尾留了"外部评审""C 判"两行，由人填。数据默认是 demo-vault（WS-A 还在"拆题中"），用 --vault 换成别的目录。
